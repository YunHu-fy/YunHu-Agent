# 云琥 1.3.8

当前构建 **1.3.8 / versionCode 10308** 修复本地模型“启动即退出”，并加入 Android 17（API 37）支持。

## 1.3.8 修复

- **本地模型不再启动即退**：`llama-server` 的启动参数改为按已安装引擎 `--help` 实际声明的能力下发，`--no-webui`、`--parallel` 这类可选参数在引擎不认时不再传入；一旦日志显示参数被拒，自动改用最简参数重试一次。原来只回一句 `llama-server exited before becoming available`，没有任何可查信息。
- **失败原因可读、可查**：启动失败现在返回退出码、实际端口与日志末尾几行，并把常见原因翻译成下一步动作——内存不足、缺运行库、端口占用、模型无法被该引擎加载、参数不被接受。设置页新增「查看引擎日志」，可直接读取最近一次 `llama-server` 的输出（上限 4 MiB，接口只回文本，不暴露沙箱路径）。
- **端口占用自动回退**：上一轮遗留的推理进程占着 18286 时，绑定会瞬间失败，看起来像引擎崩溃。现在会在 18000–18999 内另选可用端口，并把真实端口写回模型配置与请求地址。
- **就绪等待从 1.8 秒放宽到 20 秒**：1.5B 模型从闪存加载常超过两秒，旧窗口会把仍在加载的服务误判为已退出；现在只要进程存活就继续等，超时返回“仍在加载”而不是失败。
- **Android 17（API 37）**：兼容策略由 API 29–36 放宽到 API 29–37，欢迎页、部署校验与提示文案同步更新；编译目标升到 API 37.2 / Build Tools 37.0.0，设备诊断新增 `page_size` 字段。`targetSdk` 仍是 28——这是 Android 10+ 应用私有目录可执行的硬前提，不随版本上调。
- **16 KB 页设备的边界（如实说明）**：本包内 Chaquopy 的 10 个原生库均为 16 KB 对齐，只有 vendored 的 `libtermux.so` 仍是 4 KB 对齐。16 KB 页内核的设备加载终端 JNI 会失败，需要重新构建该库；本版按 4 KB 页设备验收，未在 16 KB 设备上实测。

本版 Python **290 项运行、2 项跳过、零失败**，浏览器六组 **88 项**全部通过，原生 JVM **70 项**，lint **66 Warning、0 Error/Fatal**。跳过项是本机文件系统静默忽略 `symlink_to` 后主动跳过，不是失败掩盖。

新生成的安装包及源码： [release APK](<dist/AndroidAgent-1.3.8-release.apk>)、[源码 ZIP](<dist/AndroidAgent-1.3.8-source.zip>)，哈希与来源绑定见 [发行清单](<dist/AndroidAgent-1.3.8-manifest.json>)。**当前构建显式使用 Android debug 签名证书，仅供开发/测试，不应作为生产升级包分发。**请先查看 [当前验证记录](<VALIDATION.md>)。没有 Android 真机可用，未宣称设备端容器部署、软件包安装、推理或系统分享实测。

## 1.3.7 修复沿用

上次部署中断后，`installed-rootfs/<distro>` 会留下不完整的 rootfs，`proot-distro` 拒绝重名安装并报 `container 'ubuntu' already exists`；原流程只把这句话原样抛回界面，用户没有出口。现在部署前先判断容器是否完整（以 `usr/bin/apt-get` 是否存在为准）：完整则直接复用；只有残留目录时给出明确说明，并在“部署 Linux”旁新增**清理并重装**按钮，二次确认后执行 `proot-distro remove <distro>` → `proot-distro install <distro>`。安装阶段若仍返回 `already exists`，也翻译成同一句可操作提示。

## 1.3.6 修复沿用

- **原生桥接补齐 `executeCommand`**：这是“运行环境操作未成功：原生桥接不支持executeCommand”的直接原因。同步入口复用 `commandStart`/`commandPoll`/`commandCancel` 的排空逻辑，保留 1 MiB 输出上限、通道准入和取消语义，超时为请求超时加 3 秒；它服务无法流式读取的调用方，不是第二个执行器。
- **PRoot 容器可部署**：缺少 `proot-distro` 时先在 Termux 内 `pkg install -y proot-distro`，再 `proot-distro install <debian|ubuntu>`，不再因宿主状态直接判失败。状态接口对未部署容器、未知发行版、运行时缺失分别返回原因，界面按原因提示，不再只显示“包状态暂不可用”。
- **工具/库目录可用**：coreutils、jq、yq、curl、build-essential、git、apktool+JADX、adb、Node.js LTS 分别映射到 Termux 的 `pkg install -y` 与容器的 `apt-get install -y`；Ollama 只在 Debian/Ubuntu 容器内安装固定版本的官方 ARM64 发布包（v0.40.11，1,564,235,434 字节），先 `sha256sum -c -` 校验再解包，并要求至少 6 GiB 可用空间。
- **Node.js LTS 版本可见**：安装后可用 `probe=true` 回读实际 `node`/`npm` 版本，而不是只显示“已安装”。
- **硬件加速开关**：模型设置新增“硬件加速（仅本地模型）”分组，含 CPU 硬件加速、GPU 硬件加速、NPU 硬件加速与 Anima 低内存模式。四项默认关闭；只有当前端点被识别为本地模型时才能操作；使用第三方模型（地址 + 密钥）时全部锁定为关闭。GPU 与 NPU 互斥，且需本地引擎上报对应后端才可勾选，未上报时保持禁用并说明原因。
- **体积没有缩水**：release APK 从 1.3.4 的 40,642,046 字节、1.3.5 的 40,727,290 字节、1.3.6 的 40,757,346 字节、1.3.7 的 40,758,322 字节到本版 40,764,470 字节，逐版只增不减；debug 包稳定在约 60.9 MiB。功能目录、终端源码与工具链均未删减。

## 历史基线：1.1.0 功能更新

- **首次引导只需完成一次**：风险同意、所选通道确认和环境检测全部成功后记录完成状态；以后正常启动直接进入会话，不重复弹出引导或执行整套检测。可从权限设置主动重新打开。保存的 Root/Shizuku 选择不是授权，进程重启或服务恢复不会静默重放提权；需要时由用户再次明确配置。
- **多个独立模型配置**：每项分别保存服务 URL、模型名、API 密钥引用、上下文窗口、最大输出、推理能力/级别和图片能力。输入区选择本次模型；任务提交时冻结配置与密钥快照，随后切换、编辑或删除配置不改变正在运行的任务。
- **Android 安全保存模型密钥**：Android Keystore 中的 AES-256-GCM 主密钥加密每个配置的 API 密钥，使用随机 IV 和凭据引用绑定的 AAD；普通配置只保存引用，偏好文件只保存密文。桌面预览仍是 `memory_session`，重启需重新输入。
- **上下文与能力控制**：保守估算全部上下文、工具定义、图片预算并预留最大输出；超出预算明确拒绝，不静默裁剪历史或附件。推理模型发送 `reasoning_effort`（low/medium/high）；图片仅在声明支持图片的配置下启用，兼容性取决于实际模型服务。
- **文件/图片附件**：每条消息最多 8 个，单文件最多 20 MiB，合计最多 30 MiB。UTF-8 且无 NUL、大小不超过 512 KiB 的非图片附件在 1.1.0 中内联；其他文件保存在私有工作区并向模型提供工具可用路径，不声称能自动解析任意二进制格式。图片按 `image_url` 内的 data URL 发送。

## 历史修复：1.0.3 私有目录路径校验

部署不再比较canonicalPath字符串，改用只读stat核对应用filesDir与固定Termux目录的设备号、inode、目录类型和所属UID。相同目录的/data/user/0、/data/data或挂载别名可以通过；不同/缺失/无权访问目录仍拒绝，保留实际路径、身份与读取错误诊断。暂存目录发布时再次核对映射，并通过固定路径别名执行同父目录重命名，避免跨挂载点发布。

当时的 1.0.3（versionCode 10003）记录为与本项目 1.0.0–1.0.2 使用同一证书，可覆盖升级后重试部署，无需卸载或清除数据；这不是本次 1.1.0 验签结果。本次报错发生在解压前，不需要为此重置环境。未连接设备，不声称已确认用户ROM的具体映射；若仍不匹配，请提供新版实际目录与路径诊断。

## 安装前必读

- 支持 ARM64 Android 10–17（API29–37），不支持 32 位 ARM / x86。
- 为复用官方 Termux 工具的固定路径，应用包名使用 com.termux，目标 SDK 为28。应用不是 Termux 官方版本。

## 完全权限与黑名单

完全权限是**用户委托本任务自动执行命令的模式**，不是额外的 Android 权限。启用前需在当前页面明确确认，提交任务时记录模式快照；MCP 调用不能借模型参数自行打开该模式。

黑名单使用区分大小写的规则：

- 普通文本 / substring:TEXT：匹配完整脚本中的字面子串。
- glob:PATTERN：对整个脚本做 fnmatch 匹配，星号可匹配换行。
- 完全权限也不跳过黑名单，执行前及审批后重新检查。

这是用户拒绝列表，不是可证明的 shell 沙箱。获得 Root 并开启完全权限后，AI 确实可能修改系统或读取所选权限可访问的文件；应先备份数据，避免将未经信任的内容当作操作指令。

### 配置、密钥与任务快照

每个模型配置独立持有服务 URL、模型名、API 密钥引用、`context_window`、`max_output_tokens`、推理开关/默认级别和图片能力。输入区选择配置只影响新任务；任务创建时取得不可变选择（含当时的密钥），运行中不会因全局配置变更而串用另一模型或密钥。改变已有密钥的端点时，后端要求重新输入、明确清除或显式重新绑定密钥，避免自动将旧密钥发送给新服务。

Android 使用 Android Keystore 的 AES-256-GCM（随机 96-bit IV、128-bit tag、凭据引用 AAD）加密各模型 API 密钥，密文存于应用私有偏好设置。一个 Keystore 主密钥保护多个独立凭据记录，不是每个配置都创建一个新的 Keystore 主密钥。不保证硬件安全芯片/StrongBox，也不将密钥同步或导出；备份/设备迁移已禁用。密钥不可解密时明确要求重新保存，不降级为明文。明文仅在输入、解密和请求等必要运行内存中使用，不进入普通配置、启动数据或浏览器存储。

桌面模式明确报告 `memory_session`，只在当前进程中保存 API 密钥，重启需重新输入；亦可通过 ANDROID_AGENT_API_KEY 环境变量提供。配置导出只含非密钥模型元数据，导入不会恢复密钥、完全权限、令牌或数据发送同意。

### 上下文、最大输出与推理

`context_window` 是真实模型支持的窗口预算，`max_output_tokens` 预留输出；两者之差是可用输入预算。固定启用的 `ContextSession` 在输入估算超过这部分预算的 **75%** 时自动整理，目标压到约 **58%**，必要指令和最新请求等保留内容会影响最终比例。估算包括 UTF-8 字节、消息/工具框架、工具定义和每张低细节图片 4096 的预算；它保持保守估算，不把字节数随意除以常数冒充精确 token 数。压缩后仍不能容纳必要内容会明确报错，应减少输入或调整真实窗口/输出预留。

整理会先保存原文，再把旧轮次、长文本/附件文本或历史图片转成有标记的摘录、摘要和记录 ID；完整工具调用及结果按组处理，避免只有调用却没有对应结果。历史图片归档后可以不在当前请求重发，当前请求的数据量因此变化。原始文件或记录的可读入口仍保留，这不是无痕删除历史。除记忆读取外，工具完整返回 JSON 经应用脱敏后写入归档，原始工具结果超过 **6000 字节**时向模型提供摘录、状态与 `record_id`，按需取回；`memory.recall` 的分页结果直接交给模型，不重复经过这道 6000 字节摘录，读取页仍受整体上下文预算约束；执行器或原生层自身的 stdout/stderr 输出上限仍然有效，归档不恢复早已被执行器截断的字节。

`memory.recall` 只能由所属对话内的任务读取。省略 `record_id` 时，`offset` 表示索引的记录偏移，每页最多 `min(40, limit)` 条，返回 `next_offset`、`total_records`、`has_more`；`query` 在当前对话的所有档案正文中做精确字串过滤。指定 32 位十六进制记录 ID 后，`offset` 改为该记录的字符偏移，`limit` 为 **1–8192 字符**（默认 4096），`query` 从指定偏移定位原文；结果包含 `next_offset`、`total_chars`、`has_more` 和原文片段。偏移均从 0 起，查询最多 200 字符。读取本身不生成新的归档记录，避免索引漂移和回忆内容反复复制；分页返回不再次做 6000 字节摘录，仍受整体上下文预算控制。原文保存在 SQLite `context_records` 中，通过记录 ID 和此读取工具访问；文件系统路径用于标记实际操作对象。操作的实际文件路径/工作目录也随事实保存，删除对话会级联删除其记忆、检查点和归档。

每轮、每次工具后和终态将目标、摘要、操作、状态、路径、退出码与原文 ID 保存到 `task_checkpoints` / `context_memories`。这些内容只作为对话内的历史数据，不是系统指令，不恢复完全权限、Root/Shizuku 授权或密钥。语义摘要与真实任务复用同一个不可变 `ModelSelection`，完整保留已选端点、模型、密钥、推理启用状态和推理级别；仅对本次摘要请求将输出上限设为 `min(768, max_output_tokens)`，不更改模型配置。请求静默、不带工具，也不把摘要增量写入用户回答；摘要请求同样超预算或服务不兼容/不可用时回退为摘录，不执行摘要返回的操作。它与当前任务共用取消、时限和网络中断控制。中断/服务重启不自动重放修改操作，下次由用户提交新任务并先只读核对设备/文件实际状态。

普通模型发送 `max_tokens`；开启推理后发送 `max_completion_tokens` 与 `reasoning_effort`（low/medium/high），输入区可选择本次任务级别。服务必须支持这些具体参数。能力开关是用户配置，不会赋予服务本来不支持的推理或图片能力；不同提供商不保证以相同方式实现“思考”开关，也不承诺取得模型内部思维链。

助手正文按任务完整累计，正常完成的整段模型回答也写入 `assistant_response` 归档。任务累计可见正文上限为 **8 Mi 字符（8×1024×1024）**，到达上限会明确报错并保留已经收到的内容；单轮流解析还按请求采用更小的动态限制。界面显示、上下文压缩和执行器输出分别有各自边界，不能把原生 stdout 截断误写成完整设备输出。

### 模型流读取与中断

[标准库流解析器](<android_agent/model_stream.py>)逐块使用 `read1` 读取 SSE/JSON，SSE 保留当前事件而非整条 wire 响应；兼容分块 UTF-8、CRLF/多行 data、注释/心跳、`[DONE]`、`finish_reason` 与 usage。首段非空正文立即显示，之后约每 2048 字符或到达 0.1 秒的下一解析检查点批量显示，完成时刷新尾段；没有后台刷新线程。推理内容只计入预算，不展示为正文。

每轮按输出上限动态设置安全预算：wire 16–128 MiB、事件默认 8 MiB、完整 JSON 8–16 MiB；正文采用 32 字符/输出 token 的宽松防护预算，不是精确 token 计数。语义预算合计正文、推理和参数，默认至少 300,000 字符、最高 8 Mi 字符。每轮最多 8 个工具，每个参数仍最多 300,000 字符。wire 上限是累计接收量，不等于预分配 RAM 或进程内存上限；UTF-8/Unicode/JSON 临时副本还会额外占用内存。

未收到完整结束即 EOF 会报不完整响应，仅当尚无可见正文时允许请求级重试；`finish_reason=length` 明确报告截断，不派发任何工具。格式错误、不完整参数或部分工具组同样不派发，避免执行部分生成的修改操作。取消、任务截止时间及请求最长 90 秒的 socket 中断仍由任务核心控制，已显示正文保留。[1.2.0 历史专项日志](<artifacts/python-v1.2.0-stream.txt>)记录 42 项通过，含 40 项新增解析器测试；其中 2 项既有回归不另计作新增测试。

### 附件与数据发送边界

- 每条消息最多 **8 个附件**；按解码后原始文件大小计，**单个 ≤20 MiB，合计 ≤30 MiB**。仅有附件也可提交任务；前后端都会验证限制。
- 文件存放于私有工作区 `attachments/<随机ID>/payload`（显示文件名仅作元数据），模型收到名称与工作区相对路径，工作区工具可据此处理文件；通用 shell 仍遵循所选运行环境/通道的真实访问权限。
- 非图片文件只有在 **≤512 KiB、合法 UTF-8 且无 NUL** 时进入可内联文本；自动整理可先归档，再以摘录和记录 ID 缩小模型输入，完整文件仍保留在附件路径。更大文本或其他二进制文件只提供路径，不伪称内置 PDF/Office/压缩包解析器。
- PNG/JPEG/GIF/WebP 校验 MIME 与文件头；新图片要求当前模型配置支持图片，以 Chat Completions 的 `image_url` 内容块、`data:<mime>;base64,...` URL、`detail: low` 发送。历史对话切到不支持图片的配置时，用明确文字注明历史图片未发送，原图不会送给该模型；自动整理也可将历史图片归档并用明确标记替代，当前提交图片仍按当前配置能力验证。
- 发送给配置的模型服务可能包含对话、内联文本、图片、用户要求的设备信息和执行结果，以及同一服务上的语义压缩请求。普通二进制不会仅因上传就被自动全文发送，但后续工具读取的内容可能进入上下文。提交前确认附件与数据发送范围；应用本身不添加遥测。

## MCP

提供 MCP2024-11 的工具、资源及提示词接口。通用命令名称为 shell.execute，模型函数名映射为 shell_execute。工作区助手及三个工作流也可被 MCP 使用，不再通过旧工具开关授权。`memory.recall` 另要求当前任务所属对话，读取本身不执行历史脚本，也不允许仅凭记录 ID 跨对话访问。

推荐桌面客户端使用标准 stdio，先启动桥梁：

~~~json
{
  "mcpServers": {
    "android-agent": {
      "command": "python",
      "args": ["-m", "android_agent.mcp_stdio"],
      "cwd": "D:/Users/shiquanjie/Desktop/new project"
    }
  }
}
~~~

HTTP JSON-RPC 地址为 /mcp，带 Bearer 鉴权。它实现 MCP 基础方法，但不把自定义HTTP入口宣称为完整 Streamable HTTP 传输；通用 MCP 客户端可使用 stdio。逐条确认任务需要在本地界面批准，调用方需允许相应等待时间。stdout仅输出UTF-8 JSON-RPC，诊断不混入协议输出。

## 系统与验收限制

- 应用以真实权限为界；Root、Shizuku 和厂商 ROM 差异无法用“所有指令无限可用”保证。命令可提交不等于硬件能力必然成功。
- 仅 ARM64；内置 Termux 固定 prefix 对 Android 多用户、克隆 / 双开环境存在额外限制，环境探测失败时需使用主用户或适配后的构建。
- targetSdk28是官方工具固定私有目录执行兼容性的明确取舍，不满足当前 Google Play 新上架 targetSDK 要求；不是静默达到 target35 的实现。
- 交互终端由用户直接操作，遵循系统权限；AI任务的确认模式和黑名单作用于 Agent 命令入口，不是整个设备的访问控制系统。
- 进程终止尽力覆盖独立进程组，但 Root 脚本可自行脱离进程组，重启 / 删除等操作也可能先于取消生效，不承诺撤销已发生的系统修改。
- APK没有附带大模型权重、通用无障碍/OCR或远程控制服务器；这些属于后续扩展，并非本版伪造可用的功能。
- 真机上仍需验证首启、离线部署、PTY、Root/Shizuku、前后台、厂商系统、卸载 / 更新、网络代理等兼容性。
