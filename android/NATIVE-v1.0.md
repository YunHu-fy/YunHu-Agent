# Yunhu Android 1.3.8 native contract

Version **1.3.8 (10308)** keeps the existing bridge surface and adds one read-only method, `localModelLog()`, which returns the bounded tail of the private `llama-server` log (`{ok, path, bytes, text}`; 64 KiB cap). It exists because a failed engine start could previously only be reported as `llama-server exited before becoming available` with no way to see why. The method performs no process control and no writes.

`localModelStartEx` now derives its argv from the flags the installed engine advertises through `--help` (`--no-webui`, `--parallel`, `--n-gpu-layers`, `--device`, `--prio`, `--no-mmap`), retries once with the minimal argv when the engine rejects an argument, may bind a neighbouring port when the requested one is held, and reports `exit_code`, `port`, `argument_rejected` and `log_tail` in its failure payload. `page_size` was added to `androidEnvironment()` diagnostics. Compatibility policy now accepts API 29..37 (Android 10..17); `targetSdk` stays 28 because app-private `execve` on Android 10+ depends on it.

Version **1.3.7 (10307)** carried the 1.3.6 native contract unchanged: the container recovery flow (`proot-distro remove` before a redeploy) lives in the Python runtime layer and the settings UI, adds no bridge method and changes no admission rule. Removing a container is destructive, so it only runs after an explicit confirmation in the UI.

## 1.3.6 contract

Version **1.3.6 (10306)** adds the synchronous `executeCommand` bridge contract that runtime package installation already expected, exposes the local llama.cpp backend probe, and forwards CPU/GPU/NPU/low-memory choices to the engine. Toolchain catalog entries (coreutils, jq, yq, curl, build-essential, git, apktool+jadx, adb, Node.js LTS, Ollama) are Python-side data; the native bridge only supplies the command channel and the device list. Device-side operation is not claimed as tested without a connected Android device.

[DeviceBridge](<app/src/main/java/io/localagent/android/DeviceBridge.kt>) now exposes three methods that the Python runtime package layer calls:

- executeCommand(requestJson): accepts exactly the commandStart request shape and returns one JSON result instead of a command ID. It drains commandStart plus commandPoll with the same 1 MiB stdout+stderr retention and reports exit code, duration, truncation and failure honestly. The poll deadline is the requested timeout plus 3 seconds. This is a compatibility wrapper, not a second executor: streaming events, cancellation and channel admission behave identically. Callers that can stream should still use commandStart/commandPoll.
- localModelStartEx(requestJson): forwards the selected backend flags (cpu/gpu/npu/low_memory) to the llama.cpp launcher. The flags only reach the engine as `--n-gpu-layers`, `--device`, `--prio` and `--no-mmap` style arguments; the app does not emulate acceleration it cannot detect.
- localModelBackends(): returns the engine-reported device list parsed by [EngineDevices](<app/src/main/java/io/localagent/android/EngineDevices.kt>) into cpu/gpu/npu kinds with availability. The UI unlocks GPU/NPU toggles only for entries the engine actually reports; a missing backend keeps the toggle disabled and the explanation visible.

`CommandDrain` bounds both the streaming and synchronous paths: per-chunk acceptance stops at 1 MiB of retained output, and later chunks are counted as truncated rather than silently dropped. Command draining is JVM-tested without a device.

## First run, authority, and selected documents

The first-entry flow separates an original Hello Bézier-path welcome animation and line motif, licenses/privacy, normal/Shizuku/Root choice, explicit channel authorization with read-only checks, and ready/enter. It follows the system reduced-motion preference. The activation-flow pacing is an inspiration; no Apple graphic assets are used. [FirstRunGate](<app/src/main/java/io/localagent/android/FirstRunGate.kt>) still requires native consent, selected-channel confirmation, and successful environment detection before persisting completion. A completed normal launch opens the conversation directly without rerunning onboarding/detection. The permission page can explicitly reopen setup. Legacy state migrates only when the new completion marker is absent and both native consent and enabled-service state exist; an explicit incomplete marker still opens setup.

Persisted normal/root/shizuku selection is UI preference, not renewed authority. A fresh process starts with ordinary app-UID authority. Neither returning to the conversation nor service recovery replays Root/Shizuku configuration. A failed/revoked elevated selection leaves command/terminal admission closed until explicit reconfiguration; it does not silently execute as another channel. An authorization epoch revokes old commands/PTY and prevents a delayed authorization result restoring authority after stop/channel change. Native status/diagnostics never request su. The short state lock must not be held during process, Binder, or UI waits; this is an implementation rule, not a device latency claim.

[MainActivity](<app/src/main/java/io/localagent/android/MainActivity.kt>) handles ACTION_OPEN_DOCUMENT from the authenticated local WebView. Only explicitly chosen content URIs from the current document/callback generation are eligible; navigation, teardown, and renderer exit invalidate old grants. It does not grant arbitrary filesystem access or external navigation. System provider compatibility and actual URI lifetime require device testing.

## Model profiles, secrets, and messages

Python owns independent model profiles: endpoint URL, model, API-key reference, context_window, max_output_tokens, reasoning switch/default level, supports_images. The composer chooses a profile and optional per-task reasoning override. Task creation freezes [ModelSelection](<../android_agent/models.py>) including the current secret; edits, deletion, or switching the active profile do not redirect running tasks. Endpoint changes require replacement, removal, or explicit rebinding of a saved key. Settings/startup/export payloads do not return secrets or restorable credential references; imported configuration restores neither consent nor execution authority.

[KeyStoreCredentialStore](<app/src/main/java/io/localagent/android/KeyStoreCredentialStore.kt>) uses one Android Keystore AES-256 master key to encrypt separate per-profile credential records with [CredentialCipher](<app/src/main/java/io/localagent/android/CredentialCipher.kt>): AES/GCM/NoPadding, fresh 12-byte IV, 128-bit authentication tag, and credential-reference AAD. Private SharedPreferences holds only versioned IV/ciphertext records. The non-secret model file holds references. No StrongBox/hardware-backed guarantee is made. Android backup and device transfer are disabled. Invalid/unavailable credentials fail with a request to resave; Android errors do not silently fall back to plaintext or process-only storage. Plaintext necessarily exists in request/task memory. Desktop explicitly reports memory_session and loses keys on restart; it does not claim Android Keystore persistence.

ContextSession uses a conservative UTF-8-byte estimate plus message/tool framing and a 4096 budget per low-detail image. Available input is context_window minus max_output_tokens. Crossing 75% of that input budget triggers automatic compaction toward about 58%; retained required content can keep the result above that target. It does not divide byte counts by an arbitrary token ratio or claim to use the provider tokenizer. Original long text, old turns and historical pictures are archived before replacing working context with excerpts, summaries and record IDs. Calls and their tool results stay grouped. Required content that still cannot fit fails explicitly. Normal requests send max_tokens; reasoning requests send max_completion_tokens and reasoning_effort=low|medium|high. Providers must support those parameters; no uniform provider “thinking” behavior or internal chain-of-thought output is promised.

Each actual tool-return JSON except memory.recall, after application redaction, is archived in SQLite context_records independently of bounded SSE replay events. Original tool results above 6000 UTF-8 bytes are represented to the model by an excerpt, status/exit/path facts and record_id. memory.recall pages bypass this per-result excerpt step and return the requested page directly; they remain subject to the overall context budget. This preserves the returned JSON, not bytes already discarded by the native executor or tool output limit. memory.recall is read-only and bound to the task's conversation; possession of another conversation's ID grants no access. With no record_id, offset is an archive-index record offset and each page contains min(40, limit) records; query filters exact substrings across all record contents in the current conversation. Index responses return next_offset, total_records and has_more. With a 32-hex-character record_id, offset is a character offset within that record and limit is 1..8192 characters (default 4096); query locates an exact substring from that offset. Record responses include content, next_offset, total_chars and has_more. All offsets start at zero and query is at most 200 characters. memory.recall intent and results are not archived again, preventing index drift and recursive copies of recalled data. The originals reside in SQLite and are addressed by these IDs and recall parameters; filesystem paths identify actual operation targets.

Visible assistant text accumulates without silently dropping its beginning. A normally completed full response is also archived as assistant_response. The task has an explicit cumulative limit of 8 Mi characters (8×1024×1024); exceeding it raises an explanatory error while retaining prior content. Each parser round also has a smaller dynamic request limit. Existing native stdout/stderr caps remain independent; response archival cannot recover bytes already truncated by an executor.

After each model round/tool and at terminal state, task_checkpoints and context_memories retain goal, summary, operations, actual status/path/exit and archive IDs. Conversation deletion cascades through those tables. Historical operation channel/runtime facts do not constitute restored authority; credentials and grants are not restored from memory. Memory enters the conversation as labeled historical data, not a system message. Semantic compaction reuses the identical immutable ModelSelection object from the real task, preserving endpoint/model/key and reasoning enabled/effort. Only this summary request overrides its output cap to min(768, profile.max_output_tokens); it does not edit the selected profile. The request is silent, has tools=[], and emits no on_text updates into the user's answer. Summary requests that exceed the same context limit or encounter unavailable/incompatible service behavior fall back to excerpts. The request shares the real task's cancellation, deadline and I/O ownership, so cancellation closes its socket too. Interruptions or service restarts never automatically replay modifications. Continuing requires a new user task and a read-only check of actual state before further changes.

[Attachments](<../android_agent/attachments.py>) allow up to 8 per message, 20 MiB each and 30 MiB total decoded bytes. Files are retained at private workspace attachments/<random-id>/payload with display names kept as metadata and safe relative tool paths. Non-images of at most 512 KiB, valid UTF-8 without NUL, are eligible for inline text. Automatic compaction may archive that text and use an excerpt plus record ID; the complete attachment file remains at its original workspace path. Other files receive path/name metadata for tools, without claiming automatic parsing of arbitrary binary formats. PNG/JPEG/GIF/WebP need matching MIME/header and an image-capable profile. Chat Completions receives image_url data URLs with detail=low. New images reject non-image profiles. When past image-bearing history is used with a non-image profile, an explicit textual notice says the historical image was not sent; the original image is omitted for that capability boundary. Automatic compaction may also archive historical pictures with an explicit record reference; current pictures still require the configured capability. Data sent to the configured provider can include conversation, inline text, pictures, requested tool results, and semantic-compaction requests to the same provider; the app adds no telemetry.

## Model response streaming

The [stdlib parser](<../android_agent/model_stream.py>) consumes read1 chunks for SSE or JSON. SSE retains one event rather than the complete wire stream. It accepts split UTF-8, CRLF/multiline data, comments/heartbeats, [DONE], finish_reason and usage. First nonempty visible text flushes immediately, then updates coalesce at about 2048 characters or 0.1 seconds at the next parser/read checkpoint; completion flushes the tail. There is no background flush thread. Reasoning contributes to semantic limits but is not displayed.

Dynamic allowances are 16..128 MiB total wire, an 8 MiB default event, and an 8..16 MiB JSON document. These are independent allocation/acceptance bounds, not an RSS claim or reserved wire-sized buffer; UTF-8/Unicode/JSON copies have additional memory cost. The 32 characters per configured output token is a generous safety allowance, not exact token counting. Default semantic budget covers visible text, reasoning and arguments together, with a 300,000-character floor and 8 Mi-character ceiling. At most 8 tools and 300,000 argument characters per tool remain enforced.

EOF without a complete ending is incomplete and may retry only before visible text. finish_reason=length reports truncation and dispatches no tools. Malformed frames, arguments or partial call groups never dispatch a valid subset. Core retains cancellation, task deadlines and a socket-abort timer at the earlier of the task deadline and 90 seconds per request. Parser monotonic checks alone cannot interrupt an already-blocked read.

Historical 1.2.0 [focused verification](<../artifacts/python-v1.2.0-stream.txt>) passed 42 tests in 1.791 seconds, exit 0: 40 new independent parser tests and two existing streaming/cancellation integration regressions. It includes lazy >10 MiB wire input with tracemalloc peak <4 MiB for that test, not a maximum-event or whole-process RSS guarantee. Those two existing regressions are not counted again as new tests.

## Deployment, paths, and PTY

runtimeDeploy validates package, API/ABI, primary user, path identity and free storage, refuses unknown existing prefixes, and uses a private staging directory with traversal/duplicate/expanded-size limits, pinned SHA-256 and symlinks created last. Normalized link destinations/targets remain within the compiled prefix. The official second-stage configures packages; success alone writes completion. Interruption preserves any published prefix/install log rather than silently wiping it.

Retained 1.0.3 path policy uses Os.stat directory type/owner/device/inode instead of canonical path equality. Actual filesDir and the fixed /data/data/com.termux/files must identify the same app-owned directory. It rechecks before publication, using the fixed parent alias for both rename endpoints to avoid cross-mount EXDEV. Different/inaccessible roots fail closed, with read-only identities/errors in runtimeStatus.path_check and diagnostics.environment.private_prefix_check. No write probes or privileged path repair.

TerminalActivity hosts official TerminalView/TerminalSession, matching libtermux JNI, and a real PTY with UTF-8/xterm256color, HOME/PREFIX/PATH/TMPDIR and termux-exec preload. Keyboard/control keys, resize and copy/paste are supported by the implementation. Root uses explicitly granted su and a quoted system shell. Shizuku cannot access private Termux paths and fails clearly. Channel changes close old PTY; explicit service stop cancels commands and terminal. These implementation paths are not a claim of successful device execution in this session.

## Python-only native bridge

[DeviceBridge](<app/src/main/java/io/localagent/android/DeviceBridge.kt>) @JvmStatic methods return JSON strings through authenticated loopback Python/Chaquopy. There is no addJavascriptInterface.

- commandStart(requestJson): returns ok/id or error code/message. Unique ID 1–128 ASCII token, nonempty shell text ≤128 KiB/no NUL, normal|root|shizuku, system|termux, optional absolute cwd, integer timeout 1–86400/default 60, optional environment ≤128 keys/64 KiB. Structural checks are not a sandbox; Python applies blacklist and user policy. Channel admission requires current explicit authority.
- commandPoll(id,after): sequence-numbered stdout/stderr events, done/next_seq/last_seq/first_seq/more/events_lost and final result. done requires process exit and all retained pages drained. Final stdout+stderr ≤1 MiB; event ring ≤256 KiB/256 events; 4 active/16 retained records per process. Slow consumers inspect loss/final retained result. Output is not copied to Logcat.
- commandCancel(id): isolated cancellation, PID plus /proc start-time check, best-effort SIGTERM then SIGKILL. Detached children, Root, OEM or SELinux restrictions may defeat complete cleanup; not a process sandbox.
- executeCommand(requestJson): synchronous drain of the same request shape for callers that cannot stream. Same admission, blacklist and authority rules, 1 MiB retained output, deadline of requested timeout plus 3 seconds, explicit truncation flag. Unknown keys and malformed requests fail as native_contract instead of guessing.
- localModelBackends(): engine-reported device list classified into cpu/gpu/npu with availability, plus the selected backend. localModelStartEx(requestJson) forwards cpu/gpu/npu/low_memory to the launcher; unsupported flags are not synthesized.
- Shizuku UserService polls at most 16 events per page and reconstructs final output through slices ≤32768 characters to avoid Binder overflow. Private Termux combinations fail, with no implicit fallback on disconnect/revocation.
- status()/requestShizuku()/configureChannel(channel): status reports selected/available/granted state without prompting. Root/Shizuku configuration runs off the main thread. Only explicit Root configuration executes bounded su -c id -u and requires UID0. Root binary discovery does not guarantee vendor compatibility.
- credentialRead/credentialWrite/credentialDelete(profile): access the Keystore-backed record; JSON errors do not echo secrets. openPermissionSetup() reopens setup only through a visible Activity.
- runtimeStatus()/runtimeDeploy(): installed/installing/progress/stage/error/prefix/home/version/hash/offline/support boundaries; openTerminal()/openLicenses() launch internal activities with a visible host.
- deviceState(): 5-second cache with timestamps/stale/errors for brightness/volume/battery/network/foreground history. UsageStats needs manual permission and is labeled last-resumed history, not guaranteed current foreground state.
- diagnostics(): read-only SDK/ABI/ROM/su-path/SELinux/tools/UID/private-path/storage, permissions/runtime/service/active commands; never changes settings or requests su.
- serviceControl(): start/stop/restart, user-opened battery/app/usage settings, opt-in locks. WorkManager minimum 15-minute interval, at most 3 recovery attempts per 15 minutes; persistent manual stop disables recovery and elevated authority is never restored automatically.
